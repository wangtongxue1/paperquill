# ADR 0002：每篇笔记镜像成纯文本文件

- 状态：已接受
- 日期：2026-11-12
- 相关：0001、`docs/data-format.md`

## 背景

个人笔记软件最大的长期风险不是功能少，而是十年后打不开自己的数据。云端笔记靠导出，私有格式靠厂商继续存在。

## 决定

`workspace.json` 作为单一事实源（原子写），同时把每篇非回收站笔记镜像成 `notes/*.md` 或 `notes/*.html` 普通文本文件。

- 命名：`<slug>-<id 后 6 位>.<ext>`
- 图片以 data URL 内嵌，单文件即可独立打开
- 镜像只在内容变化时写盘，改名 / 删除时清理旧文件
- 镜像是派生数据，删掉不会丢笔记

## 理由

1. 纯文本能被记事本、git、grep、ripgrep、任何静态站点生成器直接处理，不需要纸间笔记存在。
2. 用户可以直接把 `notes/` 目录纳入自己的同步盘或版本库，不必依赖本应用的导出按钮。
3. 开源项目里，这份「即使项目死了数据还在」的确定性，比任何功能都更能建立信任。

## 后果

- 每次保存除了写 JSON，还要比对并写若干小文件；已用「内容不变则不写」控制开销。
- 标题含非法字符或重名时需要 slug 与 id 后缀去重，命名规则因此成为公共契约，不能随意改。
- data URL 让 `.md` 文件可能较大，单附件限制 3 MB。

## 备选

- SQLite 单库：查询与事务更好，但用户无法用文本工具处理，违背初衷。
- 每篇一个 JSON：结构化但同样需要专门解析器。
- 只存一份 JSON：实现最简单，但「纯文本落盘」就只剩口号。
