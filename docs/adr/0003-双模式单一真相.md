# ADR 0003：双模式编辑器以当前内容为唯一真相

- 状态：**已被 ADR 0005 取代**（2026-11-12 起改为单一富文本视图，Markdown 降为源码视图）
- 日期：2026-11-12
- 相关：0001、0005

> 保留本文作为历史记录。`content` + `mode` 的单一真相模型与 `convertContent()` 仍然是
> 源码视图、导入导出、`.md` 落盘镜像的实现基础；被取代的只是「两种模式在界面上对等」这一产品决定。

## 背景

用户要求富文本与 Markdown **双模式可切换**。常见做法是同时保存 `contentHtml` 与 `contentMd` 两份，切换时各取所需。但两份副本必然漂移：批量改标签、模板插入、导入、外部编辑都可能只改到其中一份。

## 决定

只存一个 `content` 字段，配合 `mode`（`'markdown' | 'rich'`）说明它的格式。切换模式时由 `convertContent()` **原地转换**并覆盖 `content`，不新开笔记、不保留第二份副本。

- Markdown → HTML：`marked` + 内链渲染 + DOMPurify 清洗
- HTML → Markdown：`turndown` + 自定义规则
- 自定义规则保住 `[[笔记内链]]`（`data-wiki` 属性）与 `- [ ]` 待办，避免切一次模式丢语义

## 理由

1. 单一真相消除同步问题，所有功能（搜索、导出、镜像、剪藏、批量操作）只读一个字段。
2. 落盘格式与模式一致：Markdown 笔记就是 `.md`，富文本笔记就是 `.html`。

## 后果

- **HTML → Markdown 有损**：颜色、对齐、复杂表格、附件位置会丢，切回来也长不回原样。这是格式的信息不对称，任何实现都躲不掉。
- 切换是一次真实的转换，不是视图切换；用户需要知道这一点（在使用说明与关于弹窗里写明）。
- 富文本模式依赖 `contenteditable` / `execCommand`，不同 WebView 版本的行为可能有细微差异。

## 备选

- 双字段存两份：切换无损，但引入一致性维护成本与潜在的静默覆盖。
- 只做 Markdown + 实时预览：实现最简，但不符合「富文本所见即所得」的要求。
- 引入 ProseMirror 统一文档模型：能同时输出两种格式，但等于把 ADR 0001 否掉的复杂度又请回来。
