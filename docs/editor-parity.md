# 编辑器逐项对标印象笔记

对比基线：印象笔记 v10 桌面版 / 网页版的编辑器（2025–2026 在用的版本）。
纸间笔记基线：v2.1.0。

结论先说：**能对齐的都对齐了，对不齐的说清楚为什么，界面上不放假按钮。**

---

## 一、底层不一样，很多差异由这里派生

| | 印象笔记 | 纸间笔记 |
| --- | --- | --- |
| 内容格式 | ENML（自有 XHTML 方言），存的是 XML 树 | HTML 片段，富文本笔记同时镜像一份 `.md` |
| 编辑器内核 | 自研模块化编辑器，块级可拖拽 | 浏览器 `contenteditable` + `execCommand` |
| 数据归属 | 云端账号，本地是缓存 | 纯本地文件，`workspace.json` + `notes/*.md\|html` |

这决定了三件事：

1. 印象笔记能做到「段落 / 图片 / 表格 自由拖拽重排」，因为它把每个段落当对象管理；`contenteditable` 里拖拽重排会破坏浏览器原生的选区与撤销栈，收益远小于风险（见 `docs/adr/0001-不采用块编辑器模型.md`）。
2. `execCommand` 已被标记废弃，但所有主流浏览器仍完整实现，且在「所见即所得 + 可复制粘贴」这个场景里没有等价替代。纸间笔记用它，并在关键处（表格、图片、待办）接管 DOM 自己算。
3. 印象笔记的 AI / OCR / 录音 / 协同依赖云端算力，本机版不做，也不做「灰按钮」假装有。

## 三、统计

- **已对齐 38 项**（其中本次新增 14 项）
- **方式不同但效果到位 5 项**（图片缩放、笔记内链、剪藏、模块插入、拼写检查）
- **明确不做 9 项**（格式刷、行距、行内代码按钮、图片标注、合并单元格、录音、思维导图、专注模式、粘贴附来源）

每一项「不做」都能在界面上找到替代路径，没有留空壳按钮。

> 2.2.0 起富文本改用 **Tiptap / ProseMirror** 内核（同 Obsidian、Joplin、Notion 的思路），
> 上面「已对齐」的项都是内核命令实现，不再是 `execCommand` 拼字符串。存档格式没变，
> 详见 [ADR 0007](adr/0007-编辑内核改用-ProseMirror.md)。
>
> 2.3.0 补的是这条链路的上下游：导入（覆盖 / 追加 / 新笔记）、导出 PDF、附件回收、
> 画板与流程图、语音视频、源码视图语法高亮。插入的时间 / 外链 / 内链 / 附件各有自己的
> 配色与字重，扫一眼能分清「这是我写的」和「这是插进来的」。
>
> 2.3.1 按反馈收敛了几处：视图切换只留在底栏右下角（编辑区上方不再重复一组），
> 插入的时间戳可点开重选年月日时分，导出 PDF 改成真正落文件、打印单独一项。

## 四、这一版新增的东西怎么验

```bash
pnpm build                                   # 类型检查 + 打包
npm run verify:editor                        # 真编辑器内核断言，38 条
npm run verify:pdf                           # PDF 容器结构断言，12 条
python tools/make_singlefile.py .temp/zhijian-probe.html
npm run verify:pdf-ui                        # 端到端导出一次 PDF 并校验字节
npm run verify:ui                            # 单文件版真点一遍，52 个观测点（每次全新 profile）
```

- `tools/verify_editor.ts`：在真浏览器里挂起**真实的 Tiptap 编辑器**（与线上同一份 `buildExtensions`），验证存档往返、待办回车续行、空项回车跳出、勾选写进文档模型并落盘、表格增删行列、代码块语言、内链往返、行首语法（`[]` / `[x]` / `#`）、撤销，共 **38 条断言**。
- `tools/pdf-writer-probe.mjs`：不启浏览器，直接用 tsc 把 `src/pdf-writer.ts` 编成 ESM 跑一遍写 4 页 PDF，再按规范回读——每处 xref 偏移必须真的落在 `n 0 obj` 上、`/Length` 等于实际流长、`startxref` 指向 xref 表，共 **12 条断言**。这类错误不会在界面上报出来，只会变成「导出的 PDF 打不开」。
- `tools/ui-probe.py`：Edge headless 打开单文件版，点开笔记 → 切富文本 → 数工具栏控件 → 点复选框（勾上 / 删除线 / 方框可见 / 切笔记后仍在）→ 表格菜单 → 六色取色板（含「点得到」检测）→ 真实上传一张 PNG 并调宽度 → 开附件预览 → 导入文件并选「追加到末尾」→ 插入一段音频 → 打开画板画两个矩形并用连线连起来 →
保存后正文出现快照 → 删掉正文里的图看附件是否被回收 → 切源码视图并点复选框回写 →
插入时间戳并点开改成指定时刻 → 点侧栏「新建」下拉（含 `elementFromPoint` 命中检测，防遮罩抢点击）→
量搜索框宽度与居中偏移 → 读深色主题下 `--text` 的相对亮度 →
在源码视图里灌两组待办样例，比对「高亮层去掉标签后的文字必须与源码逐字相同」、
待办标记的颜色 / 勾选态 / 正文淡化，共 **52 个观测点**。
  脚本每次跑都用全新的浏览器配置（`mkdtemp`），避免上一轮改过的 localStorage 带进来；
  关键项按**精确期望值**比对，不只是「不是 false」。
- `tools/pdf-ui-probe.py`：单独跑「导出为 PDF」——它会真的走一遍 html2canvas（慢、按真实时间走，
  不跟虚拟时间快进混在一起），把产出的字节捞回来验 magic number、页对象数、`startxref`、`%%EOF`
  和图像字典，共 **9 项**。

两个脚本都是可重跑的，不依赖人工点。

## 五、后续还能补的（按性价比排序）

1. **行内代码 / 高亮快捷键**：`Ctrl+`` 与 `Ctrl+Shift+H`，需要先把行内包裹写成 range 操作，避免 `execCommand` 把相邻文字一起包进去。
2. **表格列宽拖拽**：给 `th` 加手柄改 `style.width`，纯 DOM 操作，风险低。
3. **图片裁剪**：比标注简单，只需 `clip` 出新的 data URL 并新增一条附件。
4. **粘贴时自动去字体字号**（保留结构）：现在保留源样式，从 Word 粘过来偶尔会带奇怪字体。
